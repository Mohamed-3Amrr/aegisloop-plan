# AegisLoop · تسليم واضح ومساحة أكبر للتطوير

## اتفقوا على الحد الفاصل، وسلّموا الشغل الكامل

كل تاسك لها صفحة Outputs مرتبطة بصاحبها وبالـworkflow. الصفحة تحتفظ بكل الملفات ومعايير القبول الأصلية. عقد التكامل المقترح يحدد شكل البيانات التي يحتاجها المستهلك كي يبدأ؛ لا يحذف مسؤولية تنفيذ الكود أو البحث أو الاختبارات.

1. المنتج والمستهلك يراجعان الحقول، الهوية، الوحدات، حالة البيانات الناقصة وإصدار العقد. العقود الجديدة مقترحات v1 تحتاج مراجعة؛ ليست موافقات من الفريق.
2. المستهلك يحمل ملف reference ويبني ضد نفس الشكل. بيانات المصادر العامة حقيقية؛ جهاز REFERENCE-UBUNTU-01 لم يُجمع منه شيء. installed_version ووقت الرصد والنتائج غير المقاسة تظل مجهولة.
3. المنتج يسلّم الملفات الفعلية مع packet يصفها: mode=delivered، مصدر البيانات الصحيح، revision، وقت الإنشاء، المخرجات وبصماتها. provided يتطلب SHA-256؛ البصمة تصريح في الملف وليست تحققًا من محتوى خارجي لم يُرفع.
4. افتح Swap lab، استورد الملف، راجع الأخطاء والتغييرات، ثم اختر Delivered packet. التحويل يغيّر مزود البيانات في تجربة الموقع المحلية؛ reference يظل متاحًا للرجوع. تحميل helper في المشروع الفعلي يوفّر نفس مدخل القراءة؛ توصيله بكودكم ومراجعة المنتج والمستهلك مطلوبان.
5. التحقق من الشكل لا يثبت الصحة أو اكتمال التسليم أو التصريح بالتشغيل. التجربة لا تنفّذ جمعًا أو إصلاحًا. بوابات التشغيل والقبول الأصلية تظل مطلوبة.

## إزاي نزوّد قيمة الشغل؟

اختار تحسينًا مرتبطًا بتاسكك، بفرضية ومقياس ووقت محدد. مثال C05: إضافة architecture وservices وجودة الجمع، ثم قياس عدد حالات unknown التي حلتها الأدلة الإضافية. عدد الحقول وحده ليس دليل تحسن.

احفظ البيانات الإضافية في fields أو extensions. المستهلك القديم يحتفظ بها ويستمر مع الحقول الأساسية. اعرض مثال قبل/بعد على صاحب التاسك المستهلكة. بعد ثبوت الفائدة والاعتماد، أضفها للإصدار التالي. فشل فرضية بتجربة سليمة نتيجة مفيدة؛ لا تختلق مكاسب أو تضف نطاقًا بلا ميزانية.

## التغيير والترحيل

- إضافة اختيارية متوافقة: إصدار minor، reference جديد، مثال لاستهلاك الإضافة، اختبار المستهلك القديم.
- إصلاح توثيق: patch مع سبب واضح.
- حذف/إعادة تسمية حقل مطلوب، تغيير نوعه أو معناه أو وحدته: major جديد + adapter + نافذة ترحيل. الإصدار الرئيسي غير المتوافق يُرفض في Swap lab الحالي.
- أرسل proposal لصاحب كل تاسك مستهلكة يتضمن التغيير والسبب والمثال والنتيجة المتوقعة وخطة الرجوع. الموقع يحفظ المقترح في export المحلي؛ لا يرسل رسائل تلقائية.
- عند تكييف صيغة المجال إلى packet، التكييف يكون مرة واحدة عند حدود المنتج. لا تعيد كتابة منطق كل مستهلك. احتفظ بأدلة المصدر والحقول الإضافية.

## التخزين والمشاركة

العقود والملفات المرجعية متاحة لكل الفريق على الموقع. الملفات المستوردة والمقترحات واختيار provider محفوظة في هذا المتصفح فقط. Export workspace & change log ينقلها في ملف واحد. Import workspace يستبدل مساحة العمل المحلية بعد التحقق من كل ملفاتها؛ صدّر نسختك أولًا للاحتفاظ بها. هذه النسخة لا تتضمن مزامنة جماعية أو تتبع إنجاز مباشر.

## حالة البيانات

Reference packets هي بيانات تكامل منظمة، وليست نسخًا جاهزة من 71 برنامجًا أو تقرير تجربة مكتملًا. حالة not_produced تعني أن الملف المتوقع لم يتم إنتاجه في هذا العمل. لا يوجد ادعاء بأن أي شخص انتهى أو تأخر. الأسهم من بيانات خطة المشروع الأصلية وتوضح ترتيب الاعتماديات؛ ليست جدول مواعيد حيًا.
